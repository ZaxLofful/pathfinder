# Pathfinder - EVE Online Mapping Tool

## Repository Overview

Pathfinder is a comprehensive web-based mapping tool for EVE Online that helps players navigate wormhole space, null-sec regions, and plan routes through the galaxy. The application is built with PHP backend and JavaScript frontend using a modular plugin architecture.

## Technology Stack

- **Backend**: PHP with Fat-Free Framework (F3)
- **Frontend**: JavaScript (ES6+), jQuery
- **Build System**: Node.js, Gulp, npm
- **Styling**: SASS/SCSS
- **Database**: MySQL/MariaDB
- **Code Quality**: JSHint for JavaScript linting

### Creating New Modules/Plugins

Modules in Pathfinder are self-contained UI components that can be added to the system view. Follow this pattern:

#### 1. JavaScript Module (`js/app/ui/module/system_[name].js`)

```javascript
define([
    'module/base',
    'app/render'
], (BaseModule, Render) => {
    'use strict';

    let YourModule = class YourModule extends BaseModule {
        constructor(config = {}) {
            super(Object.assign({}, new.target.defaultConfig, config));
        }

        render(mapId, systemData) {
            this._systemData = systemData;
            // Create and return your module's DOM element
            let bodyEl = Object.assign(document.createElement('div'), {
                className: this._config.bodyClassName
            });
            this.moduleElement.appendChild(bodyEl);
            return this.moduleElement;
        }

        init() {
            super.init();
            // Initialize your module
        }

        beforeHide() {
            super.beforeHide();
        }

        beforeDestroy() {
            super.beforeDestroy();
        }
    };

    // Module configuration
    YourModule.isPlugin = true;              // Mark as plugin
    YourModule.scope = 'system';             // Module scope
    YourModule.sortArea = 'a';               // Default area (a, b, or c)
    YourModule.position = 20;                // Sort position
    YourModule.label = 'Your Module';        // Display name

    YourModule.defaultConfig = {
        className: 'pf-system-yourmodule-module',
        sortTargetAreas: ['a', 'b', 'c'],
        headline: 'Your Module Name'
    };

    return YourModule;
});
```

#### 2. SCSS Stylesheet (`sass/layout/module/_system_[name].scss`)

```scss
.pf-system-yourmodule-module {
  // Your module styles here
  .your-component {
    // Component styles
  }
}
```

#### 3. Add Module Import

Add your stylesheet import to `sass/layout/module/_all.scss`:
```scss
@import "_system_yourmodule";
```

### Module System Architecture

- **BaseModule**: All modules extend this base class that provides common functionality
- **Scope**: Determines when modules are updated (`system`, `connection`, `global`)
- **Sort Areas**: Modules can be placed in areas `a`, `b`, or `c` via drag-and-drop
- **Plugin Loading**: Plugins are automatically loaded via RequireJS if properly configured

### Coding Standards

#### JavaScript
- Use ES6+ syntax where supported
- Follow JSHint rules (single quotes, semicolons, etc.)
- Use `'use strict';` mode
- Prefer `const`/`let` over `var`
- Use template literals for string concatenation

#### SCSS
- Follow BEM-like naming: `.pf-module-component-element`
- Use variables from `_variables.scss`
- Keep selector specificity low
- Use nested selectors sparingly

#### File Naming
- JavaScript modules: `system_[feature].js`
- SCSS files: `_system_[feature].scss`
- Use lowercase with underscores

### Common Patterns

#### Data Storage
- Use browser localStorage for user preferences
- System data comes from `systemData` parameter in render()
- Map data available through global `Util.getCurrentMapData()`

#### Event Handling
- Use modern event listeners: `element.addEventListener()`
- Clean up event listeners in `beforeDestroy()`
- Follow existing patterns for UI interactions

#### UI Components
- Use `Object.assign(document.createElement())` for element creation
- Follow existing CSS class naming conventions
- Make components responsive and accessible

### Testing

- Manual testing in browser with developer tools
- Validate JSHint passes before committing
- Test in multiple browsers (Chrome, Firefox, Safari)
- Verify mobile responsiveness

### Common Gotchas

1. **RequireJS Dependencies**: Ensure all dependencies are properly declared
2. **CSS Specificity**: Keep selectors simple to avoid conflicts
3. **Memory Leaks**: Clean up event listeners and timers in lifecycle methods
4. **JSHint**: Fix all linting warnings before committing
5. **Module Loading**: Plugins are loaded dynamically, core modules are loaded statically

### Integration Points

- **Route Planning**: Use existing route calculation APIs
- **System Data**: Access via `this._systemData` in modules
- **Map Integration**: Interact with map through established APIs
- **User Preferences**: Store settings in localStorage or user config

### Performance Considerations

- Lazy load heavy dependencies
- Use efficient DOM manipulation
- Minimize API calls
- Implement pagination for large datasets
- Use CSS transitions for smooth animations

### Debugging

- Use browser developer tools extensively
- Enable verbose logging in development
- Test module lifecycle events (show/hide/destroy)

This architecture supports extensible, maintainable code that integrates seamlessly with the existing Pathfinder ecosystem.
